# lib-seat-auto-demo 架构讲解

> 本文档用于技术学习：讲解"图书馆座位预约自动化"这类系统的通用架构思路。
> ⚠️ 仅限学习研究，禁止用于真实系统抢座。文中不提供任何可运行的成品脚本。

## 一、系统总体结构

一个典型的"预约自动化"系统由四层组成：

```
┌─────────────────────────────────────────────┐
│  控制台（Web 页面 / 手机浏览器）              │
│  管理账号、时段、开关；查看日志与预约记录      │
└──────────────────┬──────────────────────────┘
                   │ HTTP (JSON)
┌──────────────────▼──────────────────────────┐
│  Web 服务（Flask）                            │
│  提供 API：保存配置 / 手动触发 / 查询日志      │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  业务核心（抢座 / 签到 / 查询）               │
│  · 多账号按优先级调度                         │
│  · 成功结果写入"预约日志"                     │
│  · 两个守护线程：自动抢座、自动签到            │
└──────────────────┬──────────────────────────┘
                   │ HTTP
┌──────────────────▼──────────────────────────┐
│  目标系统（图书馆预约平台的 HTTP 接口）        │
└─────────────────────────────────────────────┘
```

## 二、三个核心技术点（本 Demo 对应的学习目标）

### 1. Web 请求（web request）

### 2. 调度（scheduling）

- "每天只触发一次"：持久化标记（写入配置文件），服务重启不重复

### 3. 认证（authentication）
- 登录参数加密传输（AES 思路）——见 `demo/01`
- 登录态维持、接口按固定顺序协作（查状态→取位置→上报→动作→复核）——见 `demo/06`

## 三、抢座链路的通用顺序

```
① 构造任务：账号配置 → 每个账号每个时段一条任务
② 排序：按优先级（数字小者先执行）
③ 等待放号时间（准点执行）
④ 逐个任务：
   登录 → 获取页面令牌 → （滑块验证）→ 提交预约
⑤ 解析返回：按"真实返回的时段/座位"记录
⑥ 补录到预约日志（精确去重，清理重叠旧记录）
```

## 四、签到链路的通用顺序

```
① 每天定时"查询预约"，把目标系统的真实预约补录进本地日志
② 守护线程扫描日志：
   今天 + 未签到 + 开始时间在 [预约时间 ± 窗口分钟] 内 → 触发
③ 单次签到：
   查预约 → 取位置 → 上报位置 → 提交签到 → 按返回分类判定
④ 成功 → 标记"已签到 + 签到时间 + 来源"；失败 → 留待重试
```

## 五、数据模型（通用）

**账号配置**（一份 JSON）：
```json
{
  "name": "示例账号",        // 显示名
  "username": "demo_user",   // 登录标识（示例）
  "roomid": "6487",          // 场地 ID
  "seatid": ["082"],         // 备选座位列表
  "priority": 1,             // 优先级（小者优先）
  "auto_reserve": false,     // 是否参与自动抢座
  "auto_checkin": true,      // 是否自动签到
  "sessions": [{"start": "08:30", "end": "15:30"}]
}
```

**预约日志**（一条记录）：
```json
{
  "date": "2026-10-27",
  "start": "16:30", "end": "22:00",
  "seatid": "082",
  "checked_in": false,
  "source": "manual"   // 来源：抢座补录 / 手动添加 / 查询补录
}
```

## 六、已知的工程注意事项（学习价值）

1. **身份绑定**：目标系统通常以"登录手机号"为唯一身份；本地再怎么分账号，同手机号在目标系统侧就是同一用户。
2. **频率控制**：失败重试要有冷却，否则窗口期内会高频请求，触发风控。
3. **并发安全**：多个线程同时读写同一份 JSON 配置/日志时，需要加锁 + 原子写（临时文件再改名），否则互相覆盖丢数据。
4. **确定性错误早停**：接口返回"时间已过/参数错误/未登录"这类重试无意义的结果时，应停止重试。
5. **配置脱敏**：真实凭据不应入库、不应进 Git 仓库（见 .gitignore）。
